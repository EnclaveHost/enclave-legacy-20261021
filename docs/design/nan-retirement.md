# Nan retirement — implementation and cutover gates

Censorship resistance is the acceptance criterion. Moving every service to another Enclave-operated machine is insufficient. Enclave's wallet may decline deployments on its own hosts; a consenting independent host and sufficient independent custody quorum must continue serving. Application TLS remains inside the guest.

## Current production checkpoint — 2026-10-19

Adapter 1.0.17 is active with direct wallet-authorized uploads and the existing production restart-cache/commit-timeout fixes preserved. The Windows host `nucbox-k11-4` has accepted wallet ownership and enforces its committed local policy; that policy does not require catalog approval. Independent hosts are outside this owner's veto. The checker has moved to Windows and the Nan checker is stopped. These changes do not supply an independent custody quorum.

The live Sia/indexd/PostgreSQL writer has moved to the `enclave-storage` Ubuntu VM on minipc. Nan indexd is stopped and persistently fenced, and its PostgreSQL cluster is stopped with automatic startup disabled. `sia.enclave.host` now has four DNS-only provider A records and no Nan A/AAAA. Restricted reverse SSH routes reach the VM, where TLS terminates. A wallet-signed upload and exact readback succeeded with Nan's former storage proxy returning 503. All nine apps remained ready and all ten original guest VM IDs remained running. The source database is stale after target writes: rollback requires fencing the target and transferring its latest consistent state, never restarting the old source snapshot.

Three initial upload attempts failed at the guest's Sia egress CONNECT path. A later attempt passed without a guest restart after connections drained; the cause is not established. The earlier large CAR streaming failure also remains unresolved. Encrypted post-cutover recovery snapshots exist on the four providers without their decryption key. Those backups and static bootstrap replicas are not live independent Sia writers.

Each static replica now has its own `bootstrap-<region>.enclave.host` HTTPS origin and certificate, with public ingress forwarded to a separate loopback Caddy service. All four served the active adapter's complete CAR with ordinary TLS and CID verification. Their availability does not depend on Nan's gateway. The measurement predictor supports `SECRETS_RELEASE_PREDICT_GATEWAYS`, an explicit ordered HTTPS replica list replacing its legacy artifact gateway. Clear a legacy `SECRETS_RELEASE_CONFIG_GATEWAY` when retiring that source. Every attempt uses the pinned toolchain's CID verifier, shares a bounded fetch deadline and removes partial output before failover. No measurement, catalog, admission or secret-release check is relaxed.

The older preparation sections below describe the rollout sequence and remaining design constraints. They are not the current activation status. Full Nan retirement is still incomplete: app-zone delegation, control/identity/secret services, certificate paths, independent custody and the outage/censorship-resistance acceptance tests remain.

## Implemented and deployed

Four public signed-record directories run on the existing provider machines. They verify provider records, qualification verdicts, owner network policies and short-lived routes against chain state. Windows and metal0 publish directly; the Windows enrollment path preserves the configured directories. Duplicate gossip is skipped and lease reads are batched. The current observation is 12 active app publications across all four directories. All four are still Enclave-operated. All four now pin the deployment ledger, registry, connectivity and SessionVault factory. A fresh directory validated four providers, five policies and twelve routes with nan, enclave.host hostnames and address-book reads blocked. This establishes metadata bootstrap only, not whole-host recovery.

Legacy mirrors, BYO credentials, custom domains and the temporary public-policy bridge remain during migration. This is not an outage acceptance result and nan must remain running.

Providers and the checker publish only to the four direct directory origins. The legacy DNS/API lost routes when its old provider records expired; `scripts/network/mirror-public-providers.mjs` now pulls signed provider and qualification records into that legacy consumer. It preserves negative verdicts, uses the destination's existing verification, and holds no signing keys. This bridge keeps current DNS working until DNS/ENS migration; it does not make nan authoritative for the independent directories.

## Storage release prepared

The s3-ipfs-adapter release adds direct deployment-bound EIP-191 upload authorization, preserving HMAC compatibility. CLI and console support the direct protocol but it is not the production default until the adapter has been upgraded. Contract wallets and delegated sessions require further work. The new WASM has been uploaded to the actual adapter and fetched back with its hash checked. Publishing and changing the production deployment require its owner's hardware-wallet signatures.

The 17 active/release bootstrap CIDs are copied and CID-verified on four public replicas; all missing active WASM and config objects were seeded into the actual adapter. All 936 unique retained CIDs (4,690,923,948 bytes, from 1,239 inventory entries) are now locally CAR-verified and served on every replica. All 7,488 raw/CAR HTTP HEAD checks and full content samples passed. This is a recovery snapshot, not live backing-state replication. One 101 MB adapter CAR transfer failed after two attempts, with the final response truncated; ranged raw retrieval rebuilt its exact CID, and the resulting static CAR passed complete public readback. Streaming reliability still needs investigation. The Sia S3 guest still calls indexd on nan, backed by PostgreSQL. Both that dependency and the metadata/key recovery path must migrate before storage is independent.

## Host ownership and veto: source only, not deployed

`EnclaveHostOwnership.sol` pins a registry and establishes wallet ownership through two-party consent: the registered operator nominates the initial owner and that wallet accepts. Existing ownership can only be transferred by the old owner nominating and the new owner accepting. No administrator can set a global veto. Payout declarations never confer policy authority.

A host owner commits a local admission document with `setPolicy`. The document binds chain ID, ownership contract and host ID, and carries deployment/app-reference denials and a local choice to require catalog approval. A fresh agreeing chain quorum identifies the current commitment; a missing or mismatching nonempty document fails closed for that host. Transferring ownership clears the former owner's policy. There is no network-wide application deny list.

The custody combiner now accepts a sufficient independent quorum when Enclave answers challenges but refuses or supplies invalid shares. Thresholds, share checks and duplicate-seat exclusion remain intact. The live committee still consists of a single Enclave seat, so source changes alone cannot create independent recovery.

The proposed vault now pins `EnclaveHostOwnership` and its registry at construction. Custodian admission computes the Enclave seat from accepted ownership, never payout declarations. The image builder requires an explicit `--host-ownership` pin. Its membership reader checks fresh agreeing chain state, checks that the vault matches that measured pin, and refuses legacy vaults without that authority interface. This is a new contract/runtime deployment, not an in-place update: leave existing committees on their compatible runtime until a controlled bundle/committee migration is ready. Existing committee flags remain epoch snapshots; ownership changes affect new admissions/handovers.

Do not deploy this custody change as a completed veto migration. Remaining work includes publishing and binding host ownership, signed/measured runtime releases, activating the new wallet-based custody classification, and redistribution into an independently operated committee. Frontend/CLI explicit release selection now leaves catalog admission to each host, with moderation status displayed. Other serving paths still require review; existing production runtimes retain their old gates until explicitly activated.

### Host runtime integration (prepared, not activated)

Windows host claims, scans, forced launches and live renewal ticks now consult the host's wallet policy when explicitly configured. A refusal stops the local app before releasing its lease; it does not mark the deployment globally forbidden or permanently prevent a later retry. Linux supervisor claim/version/config gates, live audits and renewals use the same authority; its unconditional yank sweep is disabled in this mode. Resource, tenant consent, placement, isolation, publisher-fee and lease checks remain.

Activation requires `ENCLAVE_CONTRACT_PINS_FILE` plus all four settings: `ENCLAVE_HOST_OWNERSHIP`, `ENCLAVE_HOST_REGISTRY_PIN`, `ENCLAVE_HOST_CATALOG_PIN`, and `ENCLAVE_HOST_POLICY_DIR`. The directory contains public `<policyHash>.json` documents. Policy and catalog pins are read from configuration, never the mutable book. The ownership contract's registry must match the configured pin. Two independently configured RPCs must agree at a recent block; accepted wallet-policy snapshots are reused for at most 15 seconds and cannot outlive the 90-second chain freshness window. Missing ownership, unavailable quorum, unavailable committed documents and mismatches refuse locally. A zero commitment from an accepted owner means no catalog veto and no deny entries. All approval/yank checks in these two runtimes are then host-local choices. Legacy behavior remains only when this mode is unconfigured.

This mode requires an exact on-chain deployment ID: the supervisor's legacy direct, non-ledger creation API cannot satisfy wallet policy and refuses. The new contract pin file fixes the ledger, registry, catalog and proof bindings at process start in both host runtimes; the Linux address-book watcher is disabled and Windows resolution uses those pins without contacting the book. Optional payment/audit bindings are explicit, including zero for disabled services. Session factory and custody discovery entries are recorded for subsequent consumers but are not yet wired into all identity/custody paths. The production release must not be described as censorship resistant until those paths, custody and the full outage gates pass.

Capture current bindings and bytecode hashes with `node scripts/network/capture-contract-pins.mjs --book <address> --out <directory>` using agreeing fresh RPCs. Review every binding before activation; absent book entries do not prove that a legacy deployment does not exist.

After the ownership contract is deployed, prepare enrollment without a signing key using `node scripts/network/prepare-host-policy.mjs --policy <document.json> --owner <wallet> --registry <pin> --book <address> --out <new-directory>`. The supplied policy must explicitly choose its approval requirement and deny lists and bind the deployed ownership contract and exact host ID. The tool reads the active operator and accepted/pending owner through a fresh RPC quorum, refuses a different accepted owner or conflicting nomination, and writes the hash-named public policy plus ordered unsigned transactions. It resumes partial enrollment without repeating completed steps. Publish the document locally first, then re-read and simulate each transaction after its prerequisite confirms. Do not infer ownership from payout addresses or enroll an independent host into Enclave's wallet by default.

Build the shared runtime with `node scripts/build-host-admission.mjs`; `--check` verifies the committed bundle. Windows' import-closure deployment and the supervisor Dockerfile include that bundle so neither depends on a missing sibling npm installation.

## Required retirement evidence

- Independent operators and custodians selected and enrolled, with an independent quorum that can actually release.
- No required nan origin in artifact, policy, host-control, identity, DNS, certificate or custody paths.
- S3 writes, raw/CAR reads and all retained content survive loss of nan and one storage endpoint.
- Clean-host startup restores artifacts, secrets and persistent state while nan and the app owner are offline.
- New users authenticate, upload and deploy through the supported independent path.
- Wallet veto stops only its own host; independent hosting continues. Ownership transfer revokes the former wallet.
- Native ENS recovery works without enclave.host, and guest TLS renewal succeeds independently.
- A timed nan outage demonstrates these properties before services or data on nan are removed.

The proposed vault also pins its deployment ledger and SessionVault factory at construction; the compatible release reader uses that ledger and the pinned host registry. A real-chain test clears the book's ledger/registry entries and verifies that the independent custody quorum can still release. Older deployed vaults and readers retain their legacy authority path until explicitly migrated. Other serving and discovery paths still resolve mutable address-book entries; this custody change alone does not remove all global authority.

### Client catalog selection (prepared)

The CLI accepts an explicitly named catalog version for create/upgrade regardless of approval, yank or listing status. Implicit selection continues to recommend an approved, non-yanked release. The console has an All releases view, retains direct links to delisted apps, exposes every immutable version and displays moderation status in deploy/upgrade flows. Owner/session scope, minimum resources, publisher fees, rate limits and isolation checks remain. Catalog moderation is not a network-wide client veto; a host may still decline according to its owning wallet's policy. Production legacy hosts retain their old admission checks until the new host mode is activated.

### Public directory authority pins

Directories accept a complete `authorityPins` object naming `deployments`, `registry`, `connectivity` and `sessionVaultFactory`. The first two must be nonzero; zero explicitly disables either optional binding. A partial/invalid object refuses startup. With pins configured, lease/operator reads never consult the address book; unknown bindings refuse rather than falling back. Contract-owner and SessionVault policy signatures use fresh agreeing reads at the same confirmed block. EOA signatures remain checked against the deployment's verified owner.

Capture bindings and deployed bytecode hashes with `scripts/network/capture-network-authorities.mjs --book <address> --out <new-json-file>`. An explicitly verified legacy SessionVault factory can be supplied with `--session-factory` when the book entry is empty; a conflicting nonempty binding refuses. Review and copy the resulting `authorityPins` into directory configuration. This is deployed on all four public directories and all four providers; the cold-policy revision anchor remains unresolved. Route reads revalidate their snapshot when publication, policy or provider state changes during signature/chain verification. Bounded retries preserve replay floors and refuse a superseded withdrawal or policy; a concurrent accepted update no longer causes the old snapshot to omit a valid replacement.

### DNS route replicas

`DNS_READ_ONLY=1` runs the authoritative DNS responder against an explicit `ROUTE_MAP_URL`, without fleet discovery, signing keys or certificate challenge writes. It refuses a missing route-map setting and the box-control namespace. Co-locating it with a pinned public directory allows app-zone A answers to come from locally verified signed routes, with answer TTL bounded by each route's expiry. UDP and TCP, refusal of TXT mutations and expiry during directory failure are covered by tests. Raw TCP/IP-zone records are not yet supported by the signed directory response and must not be assumed migrated. This is a route-serving replica, not a certificate/namespace cutover: do not delegate production zones until independent DNS-01 issuance, control names, nameserver records and rollback have been prepared and verified. Existing nan DNS must remain available until those gates pass.

The provider entry point now accepts the same complete `authorityPins` object, including the connectivity binding used for paid service. Registry discovery and contract-owner signature checks use its chain quorum. The host privacy agent accepts these pins under `chain.authorityPins`; network policy verification uses that reader and rejects a conflicting legacy `enclaveNetwork.registry`. All four providers now run the pinned release, with unchanged WireGuard keys, restored peer counts, twelve routes and adapter health verified after each restart. The restarts caused brief control API interruptions. Host agents require a separate rollout with current process/status timestamps and end-to-end guest checks; cached readiness is insufficient. Build standalone artifacts with `node scripts/network/build-consumers.mjs OUTPUT_DIRECTORY`. The ESM bundles include a CommonJS compatibility wrapper for dependencies such as ws. Tests load the artifacts outside the repository without npm dependencies; also import-test the candidate using the target host's installed Node before replacing its running executable.

Four undelegated DNS replicas are active on the existing provider IPv4 addresses, consuming only their local pinned directory. Public UDP/TCP queries for the adapter match verified routes. Standard certificate-verified HTTPS requests using those answers reach the ready guest and its 1,239-entry inventory. This proves app routing through the staged replicas, not independent certificate renewal or full DNS migration.

### Consistent indexd recovery

`sudo scripts/storage/snapshot-indexd.sh NEW_PRIVATE_DIRECTORY` captures a quiesced PostgreSQL dump, consensus BoltDB, original configuration, exact deployed executable, optional GeoIP database and counts. It requires an active source, stops indexd, verifies its writer exited, and restarts the service before hashing the snapshot. Failure/signal cleanup attempts to restart the source. Treat the entire directory as sensitive; encrypt before transport, keep decryption material separately, and never print configuration or recovery phrases. This captures a recovery point, not a permanent write fence for cutover: the source resumes accepting writes.

A production capture stopped indexd for two seconds and resumed it. Its encrypted archive is hash-verified in root-only directories on all four providers without copying the decryption key. A network-disabled, port-free PostgreSQL 18.6 container restored the dump and started the exact deployed indexd binary with the consensus state and public GeoIP database on RAM filesystems. The recovered wallet binding loaded; scan and sync heights matched 597,924. Counts matched 1,302 objects, 530 slabs and 67 contracts, with no invalid indexes or unvalidated constraints. The temporary container and task-created plaintext source snapshot were removed after verification.

This does not verify remote slab reads, writes, a live target, wallet rotation or independent custody. For cutover, qualify target capacity, prepare TLS and DNS/endpoint access, fence the source writer and capture a final consistent state. Start only one network-connected indexd with that wallet. Once the new target accepts writes, restarting the old snapshot is not a safe rollback; stop the target and reconcile its latest state first. The existing recovery phrase exposure requires a controlled contract/wallet migration; replacing the seed in place is not supported. Nan must remain running pending these gates.

### Portable qualification checker

The consumer builder also produces `checker.mjs`. `--directories-file PUBLIC_JSON_ARRAY` supplies explicit public directory origins without shell-specific JSON quoting; conflicting inline/file arguments and invalid origin arrays refuse startup. A migration package must include the existing WireGuard probe executable and use a protected local checker key. The nine qualification checks and 4 MiB integrity payload remain unchanged. Keep the checker separate from the providers it qualifies. Moving the existing key to another Enclave-operated host does not add an independent vote.

Checker handoff must be serialized. The provider deliberately replaces an earlier probe from the same checker identity and role. Parallel source/candidate probes can therefore interrupt each other, even if the candidate does not publish its verdict. Before stopping the source, verify sufficient remaining healthy signed-verdict coverage. Start the replacement only after the source stops; require a complete newly issued round on every directory and actual guest health. On failure, stop the destination before restarting the source. Do not accept cached status or old verdicts as migration evidence.
